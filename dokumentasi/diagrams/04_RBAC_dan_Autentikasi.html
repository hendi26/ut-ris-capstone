Alur Autentikasi JWT (Login → Akses → Refresh → Logout)

sequenceDiagram actor Client as Client (Browser) participant API as FastAPI Backend participant DB as Database participant BL as Token Blacklist Note over Client,BL: === LOGIN === Client->>API: POST /auth/login {username, password} API->>DB: SELECT user WHERE username=? DB-->>API: user row API->>API: BCrypt.verify(password, hash)\nTiming-safe (anti-enumeration) API-->>Client: 200 OK\n{access_token (30 mnt, jti=uuid4),\n refresh_token (7 hari, jti=uuid4),\n user:{id,role,...}} Note over Client,BL: === REQUEST TERAUTENTIKASI === Client->>API: GET /api/v1/* \nAuthorization: Bearer {access_token} API->>API: decode_token() → payload\ncek type=="access"\ncek jti not in BLACKLIST\ncek user.is_active\ncek RBAC permission API-->>Client: 200 OK / 403 Forbidden Note over Client,BL: === SILENT REFRESH (token expired) === Client->>API: POST /auth/refresh {refresh_token} API->>API: decode refresh_token\ncek type=="refresh"\ncek jti not blacklisted API->>DB: get user (still active?) DB-->>API: user OK API-->>Client: 200 OK {new_access_token (jti baru)} Note over Client,BL: === LOGOUT === Client->>API: POST /auth/logout {refresh_token} API->>API: decode token → ambil jti API->>BL: blacklist_token(jti) BL-->>API: added to TOKEN_BLACKLIST set API-->>Client: 200 OK {message: "Logout berhasil"} Note over BL: Token lama tidak bisa\ndigunakan lagi
