4. Fitur Baru yang Diimplementasikan
4.1 Dashboard Adaptif Per Role

Dashboard sebelumnya generik untuk semua role. Sekarang menampilkan statistik yang relevan per role: Admin (5 stat: total pasien, jadwal, pemeriksaan, laporan pending, selesai hari ini), Radiolog (pemeriksaan & laporan pending), Dokter (pasien & jadwal), Resepsionis (pasien & jadwal harian), Patient (portal cards navigasi). Quick actions juga disesuaikan per role.

4.2 Integrasi PACS dengan Fallback Mock (Hybrid Strategy)

Sistem PACS diubah dari "throw error 503 jika Orthanc tidak aktif" menjadi strategi hybrid: coba koneksi ke Orthanc (timeout 5 detik), jika gagal → fallback otomatis ke 5 study simulasi dalam format DICOMweb JSON standar. Halaman Pemeriksaan menampilkan PACS Status Banner (hijau=live, biru=simulasi) dan tombol PACS di setiap row study yang membuka modal detail DICOM (metadata, daftar series, tombol buka Orthanc viewer).

4.3 PDF Download untuk Portal Pasien

Ditambahkan endpoint baru GET /patient/my-reports/{id}/export khusus untuk patient role, dilengkapi ownership check — pasien hanya bisa mengunduh laporan miliknya sendiri. PDF dihasilkan server-side menggunakan ReportLab dengan konten lengkap (header institusi, data pasien, findings, impression, watermark DRAFT). Ukuran rata-rata PDF: 415 KB. Diverifikasi berhasil: Content-Type: application/pdf, header %PDF- valid.

4.4 Role Guard Routing

Ditambahkan dua komponen route guard baru: PatientOnlyRoute (hanya patient yang bisa akses /patient/*) dan StaffOnlyRoute (patient di-redirect ke portal jika mencoba akses halaman staf). Sebelumnya tidak ada perlindungan ini sama sekali di level routing.

Dibuat folder dokumentasi/diagrams/ berisi 7 file HTML visual yang dapat dibuka langsung di browser: ERD, Arsitektur Sistem, Alur Kerja Radiologi (sequence + state diagram), RBAC & Autentikasi (matriks hak akses), Integrasi PACS DICOMweb, dan API Reference lengkap 35+ endpoint. 8. Kesimpulan

Seluruh pekerjaan teknis dalam sesi pengembangan ini telah berhasil diselesaikan. Sistem UT-RIS kini berjalan stabil dan bersih — 0 TypeScript error, 17/17 file Python syntax valid, 21/21 skenario uji PASS. Bug-bug kritis yang berpotensi menyebabkan crash produksi, kebocoran data, dan pelanggaran keamanan telah seluruhnya diperbaiki. Fitur-fitur yang sebelumnya tidak berfungsi (PDF download pasien, PACS integration, dashboard per role, route guard) kini berfungsi penuh dan telah diverifikasi secara langsung.

Sistem siap untuk tahap user testing (TAM) dan presentasi sidang capstone. Langkah selanjutnya yang direkomendasikan adalah: (1) update WSL untuk menjalankan Docker dan Orthanc PACS nyata, (2) koneksi ke PACS produksi RSI Bogor dengan mengubah 3 environment variable, dan (3) pelaksanaan evaluasi TAM dengan minimal 5 responden per kelompok.
